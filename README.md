# 我的工作台

仅在自己电脑运行的工作与生活档案 APP。采用已确认的“随手记为主＋暖白松绿”界面；本地 Markdown、JSON 和附件是原件，SQLite 只是可重建的搜索索引。

当前为 **0.1.0 本机候选版**。GitHub 档案连接与真实同步已验证，210 个原始档案已核对并索引；重复保存连接和同步时间提示也已修正。坚果云、原目录接管与旧后台交接仍待配置和验收。详见 [真实同步记录](docs/acceptance/github-sync.md)、[状态提示修复](docs/acceptance/github-sync-status-fix.md) 和 [验收矩阵](docs/acceptance/A01-A24.md)。

## 项目仓库

应用源码保存在私有仓库 [Luca-LGY/aia-personal-workbench](https://github.com/Luca-LGY/aia-personal-workbench)，包含代码、需求与设计、测试、构建配置和完整提交历史。

| 仓库 | 保存内容 | 使用位置 |
| --- | --- | --- |
| `aia-personal-workbench` | APP 代码、项目文档和开发历史 | 本项目的 Git 远端 |
| `my-ai-archive` | 个人学习、科研、运动等档案 | APP“数据与设置”中的 GitHub 档案连接 |

构建产物、依赖和工具缓存可按下方命令重新生成；个人档案及加密凭据保存在应用的数据目录，通过应用自己的备份与同步流程维护。

## 运行

已构建的 Apple Silicon 应用：`dist/mac-arm64/我的工作台.app`。在 Finder 中双击，或在本工程执行：

```sh
open dist/mac-arm64/我的工作台.app
```

本机个人版没有购买签名证书或上传商店；遇到系统授权提示，使用 macOS 对该应用提供的正常授权入口，不需要关闭系统安全设置。测试不会替你修改系统授权。

从源码运行（macOS arm64，Node 24.22.1，依赖锁定于 package-lock.json）：

```sh
./scripts/setup-node.sh
./scripts/npmw ci
./scripts/npmw run build
./scripts/start-local.sh
```

开发热更新用 `./scripts/npmw run dev`；生成应用用 `./scripts/npmw run package:mac`。没有服务器、云数据库或付费模型依赖。构建工具和依赖首次下载需要网络。

## 页面与使用

侧栏十个同级入口依次是首页总览、快速寻找、今日计划、学习数据、科研实验、运动计划、饮食计划、游戏娱乐、开发工作、数据与设置。

- 首页随手记：输入原话，核对分类、日期、性质后归档。原文与派生事项同时保存；复杂内容保留待整理，不猜测数量、热量或结论。附件作为原文件保存，不识别食物。
- 快速寻找：标题、正文、实验编号、参数和报告关键词均可查找，支持模块、类型与日期筛选，结果打开同一份档案。
- 今日计划：关联模块来源或独立待办，完成、撤销、延期、时间与优先级共用一个稳定身份。完成计划不自动变成事实或科研成果。
- 各模块有自身字段：科目笔记与疑问、编号实验与参数结果、佳明与手动运动、实际饮食与未来饮食安排、游戏进度与游玩历史、开发项目与问题版本。
- 首页显示实际数据或空状态。测试截图中的“合成示例”不会写入正式档案。

佳明页读取现有 MCP 工作流已经写入档案的快照和历史，不要求截图，不代替已有佳明采集任务。关闭 APP 后，APP 本身不运行同步。关闭窗口会隐藏到菜单栏并继续运行；使用菜单栏“退出 APP”或显式退出才停止。运行期间启动时比较、每五分钟检查、修改停止十秒后检查，也可在首页点击立即同步。

## 数据在哪里

默认目录：`~/Library/Application Support/AIA-Workbench`。

| 内容 | 默认位置 | 要点 |
| --- | --- | --- |
| 档案原件和附件 | `archive/` | 接入现有目录或恢复后可能位于用户选择的位置 |
| 档案身份、映射、删除与恢复标记 | 档案下 `.aia/` | 保留这些元数据以维持跨端身份 |
| 事务、对象、同步日志、草稿 | 当前状态目录 `state/`、`drafts/` 等 | 不是可随意丢弃的缓存；完整备份会收录必要状态 |
| 搜索索引 | 当前状态目录 `cache/index.sqlite` | 设置中可重建，不是唯一数据来源 |
| 连接与凭据 | 当前状态目录 `settings/`、`credentials/` | 凭据使用系统加密；不会进入云档案或普通导出 |
| 当前工作目录指针 | 默认目录 `settings/workspace.json` | 接入／恢复后指向选定档案及独立状态目录 |

请使用 APP“导出完整备份”，不要只复制 SQLite 或单个业务文件夹当成完整备份。首次接入、重大迁移和恢复前保留独立备份。完整备份包含原件、附件、草稿和必要历史，逐文件校验 SHA-256；不包含凭据、可重建缓存、锁或 Git 提交历史。

恢复先检查 ZIP，再恢复到新的独立目录，不覆盖当前档案。恢复后暂停云端发布，重新配置连接、核对当前差异并明确选择继续合并；不会把旧版本立即覆盖云端。备份含个人原文和附件，应存放在自己掌控的位置。

误删记录可在“数据与设置→已删除记录”按标题、删除时间和来源找回，恢复保持原ID。原内容缺失或校验失败时保留删除标记，使用有效完整备份恢复。

损坏的搜索缓存会隔离后重建；坏连接配置停用云端但保留原文件，本地继续可用。同步历史损坏会停止发布，避免覆盖原历史。若档案位置、事务或启动页面无法读取，恢复窗口可在Finder定位数据、从完整备份恢复到新目录、重新打开或退出，不会偷偷切换空档案。可执行脚本和未知类型附件只在Finder定位，普通文档按允许类型打开。

## 配置同步

在“数据与设置”填写专用连接，密码／令牌不要发到聊天中。

1. 坚果云：为 APP 指定独立 WebDAV 文件夹，填写账号与第三方应用密码，保存后测试连接。GitHub：填写档案库所有者、仓库、分支与仅授权该库的限定令牌（Contents 读写、Metadata 读取）。两端可单独启用。
2. 先检查云端和本地目录，再核对完整差异，确认档案身份后开启同步。验证连接成功只说明可连接，不表示文件已经同步。
3. 接入已有档案前，通过源目录只读核对和完整备份；旧 Git 同步工具必须确认暂停且没有在途写入。APP 不会擅自停止原后台。详见 [真实接入步骤](docs/acceptance/real-data-onboarding.md) 和 [后台交接](docs/acceptance/background-handoff.md)。
4. 初次整库迁移生成绑定源指纹和目标版本的清单；源变化须重算，限额或中断后可回读并重试。迁移普通工作文件和附件，排除 `.git`、被忽略文件、凭据与设备状态，不宣称把 Git 历史复制到坚果云。

本地、GitHub、WebDAV 由同一个协调器比较，各云端独立记录成功时间。实际通过授权工具写入档案的聊天内容才能接回 APP；仅留在聊天中的内容不会被读取或假报归档。冲突保留候选，支持选择、手动合并和保留两份；不会覆盖式强推。授权失败需更新连接，限流等待服务端要求的时间。无网络仍可保存本地，之后补传。

系统加密暂不可用时不会明文保存凭据，本地档案和编辑仍可使用；恢复、换电脑或系统无法解密时，在 APP 重新填写连接。ChatGPT／Codex 已登录的插件凭据不会自动交给这个独立 APP。

## 验证与限制

```sh
./scripts/npmw run test:all
```

完整门禁依次运行类型检查、lint、单元、集成、打包与全部 Electron 测试，其中包含真正启动 `.app` 的持久化测试；失败即停止，不跳过打包测试。单项命令见 package.json。所有自动化使用临时目录与合成数据，不触碰真实主库、账号或佳明数据。

详细结果见 [发布检查](docs/acceptance/release-checklist.md)、[视觉复核](docs/acceptance/visual-review.md) 和 [实施记录](docs/implementation-progress.md)。本版暂不含多人登录、Android、云数据库、完整 Obsidian 接入、通用聊天监听或付费 AI；未来按独立档案身份和模块接口扩展。
