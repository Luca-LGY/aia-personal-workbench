# GitHub 连接状态提示与重复保存修复

日期：2026-10-26（Asia/Shanghai）。

## 问题与原因

用户反馈连接 GitHub 后再次提示未同步或报错。现场连接实际上为 `verified`、revision 8，同步为 `synced`，待处理、冲突和警告均为 0。

两处原因：连接卡片将所有已验证连接固定显示为“验证成功，尚未同步”，即使真实同步已完成；重复保存相同公开配置且密码框留空时，服务仍清除验证、增加版本，使安全同步暂时停止，要求再次验证。

## 修复

- 连接卡片只显示认证事实“连接验证成功”，实际同步阶段继续由首页、页脚和“同步与变更”展示。目录检查说明和保存提示也不再声称整个档案尚未同步。
- 已启用的连接，公开配置相同且没有提供新凭据时，先确认原凭据仍存在，再将保存视为无变更操作：不重写配置、凭据或版本，不发送重新同步通知。
- 更换仓库所有者、仓库名、分支、显式替换凭据或重新启用仍清除旧验证；缺失凭据仍拒绝保存。没有放宽认证或同步保护。
- 尚未验证的连接直接提示点击对应的“测试GitHub连接”或“测试坚果云连接”，不再要求反复保存。
- 未修改布局、页面缩放、配色、真实档案内容或云端权限。
