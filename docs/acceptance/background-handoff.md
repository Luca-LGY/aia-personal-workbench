# 原后台交接与回滚

状态：待真实账号配置与当刻核对，本次未执行停止、暂停、重载或真实库写入。

原审计证据在docs/audit/existing-sync.md，仅为历史时点。旧工具`.git/archive-sync.lock`与APP真实路径锁不同；取得APP锁不证明旧工具已停止。

## 接管门禁

1. 保留独立可恢复的工作文件备份，以及本机专用的完整Git/索引/未传对象、设备身份、配置、回执、plist和工具版本回滚资料。不要把凭据上传云端或写进普通备份。
2. 核对原工具与仓库/分支/来源路径属于本次同一档案，再将原工具设为暂停并停止其LaunchAgent。KeepAlive意味着只杀进程不足以交接。
3. 确认旧进程和在途写入已结束，重做最终清单与未传状态；APP接入检查会拒绝未暂停或仍加载的已知原文件同步工具。
4. 切换同一份本机档案后保持发布未启用，重新验证各端并核对当前比较，再由单一协调器接管文件同步。
5. 佳明/MCP采集、一木授权、Windows后台属于不同范围；不因本机文件同步接管而停用或改动。

## 回滚

先停止新协调器，保存新产生的本机内容、冲突、回执和待传对象；比较新旧差异后再恢复原工具。保留同一设备身份，最多恢复一个文件同步写入器。不能reset远端、删除新记录、强推或直接用旧快照覆盖全部。原Git历史仍留在原本机和GitHub，坚果云工作文件迁移不代表历史已迁移。

## 自动化边界

APP提供只读检查与接入门禁，不会擅自停止其他后台。原工具暂停、原Git回滚包和当刻进程/锁核对由后续真实接管操作在Codex完成，完成前不宣称真实交接已完成。
